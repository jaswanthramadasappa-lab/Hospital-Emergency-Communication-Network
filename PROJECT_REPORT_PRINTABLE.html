1. Abstract

Modern healthcare operations demand deterministic, zero-tolerance communication networks where life-critical emergency alerts, continuous physiological telemetry, and high-volume diagnostic imaging can traverse interconnected hospital departments without loss or excessive latency.

This project designs, implements, and evaluates a Smart Hospital Emergency Communication Network connecting seven core units: Ambulance Mobile Unit (AMB), Emergency Department (ED), Intensive Care Unit (ICU), Operation Theatre (OT), Laboratory (LAB), Pharmacy (PHARM), and Central Hospital Server (SRV).

The system provides a multi-layer network stack implementation:

  • Data Link Layer: Byte Stuffing (0x7E/0x7D) and HDLC Bit Stuffing.
  • Error Detection: 32-bit Cyclic Redundancy Check (CRC-32 IEEE 802.3) with Modulo-2 binary polynomial division.
  • Reliable Flow Control: Sliding Window protocol with Go-Back-N (GBN) and Stop-and-Wait (SW) ARQ.
  • Network Routing: Dijkstra Link-State Shortest Path and Bellman-Ford Distance Vector routing with real-time link failure rerouting.
  • Transport Layer: TCP Reno Congestion Control with Additive Increase Multiplicative Decrease (AIMD).
  • Network Analysis: In-browser Wireshark packet sniffer generating genuine .pcap binary captures, and NS-2 (.tcl) / NS-3 (.cc) simulation script synthesis.

2. Introduction & Problem Statement

In emergency clinical medicine, every second counts. In conditions like acute myocardial infarction, polytrauma, or septic shock, pre-hospital vitals streamed from an incoming ambulance must reach surgical and intensive care teams immediately.

Traditional best-effort networks suffer from packet drops, queuing delays, and link failure vulnerabilities when high-volume background transfers (e.g., multi-gigabyte MRI datasets) compete with microsecond critical alerts. This project implements a deterministic, multi-priority communication network designed to guarantee fault-tolerant delivery of critical hospital data.

4. Data Link Layer: Framing & CRC Error Detection

4.1 Byte Stuffing (Character-Oriented Framing)

Framing ensures packet boundary demarcation using dedicated Flag (0x7E) and Escape (0x7D) bytes:

Rule 1: If byte == 0x7E (FLAG) → Transmit 0x7D followed by (0x7E ^ 0x20) = 0x7D 0x5E
Rule 2: If byte == 0x7D (ESC) → Transmit 0x7D followed by (0x7D ^ 0x20) = 0x7D 0x5D

4.2 CRC-32 Polynomial Error Detection

The standard IEEE 802.3 generator polynomial of degree 32 is utilized:

G(x) = x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1
Divisor Hexadecimal: 0xEDB88320 (Reversed representation)

Sender: Appends 32 zero bits to the data bitstream and computes Modulo-2 binary long division: $R(x) = [M(x) \cdot x^{32}] \pmod{G(x)}$. The transmitted frame is $T(x) = M(x) \cdot x^{32} \oplus R(x)$.
Receiver: Computes $T'(x) \pmod{G(x)}$. If the remainder is zero, the frame is verified as error-free.

5. Transport Layer: Go-Back-N ARQ & Congestion Control

5.1 Go-Back-N Sliding Window ARQ

The sender maintains a sliding window of size $N=4$ with 3-bit sequence numbers (mod 8). The sender transmits frames within $[B, B + N - 1]$. Upon receiving cumulative ACK($k$), the sender window slides forward to $B \leftarrow (k + 1) \pmod 8$. If a retransmission timer expires, all unacknowledged frames in the window are retransmitted.

5.2 Channel Efficiency Formulations

Stop-and-Wait (N=1): η = (1 - P) / (1 + 2a)
Go-Back-N (N=4): η = N(1 - P) / [1 + 2a(1 - P + NP)]
Selective Repeat (N=4): η = N(1 - P) / (1 + 2a)
where a = T_propagation / T_transmission and P = packet loss probability.

5.3 TCP Reno Congestion Control (AIMD)

  • Slow Start: $CWND < SSTHRESH \implies CWND \leftarrow CWND + 1 \text{ MSS per ACK}$ (Exponential increase).
  • Congestion Avoidance: $CWND \ge SSTHRESH \implies CWND \leftarrow CWND + \frac{1}{CWND} \text{ per ACK}$ (Additive increase).
  • Fast Retransmit & Recovery: On 3 duplicate ACKs, $SSTHRESH \leftarrow \lfloor CWND / 2 \rfloor$, $CWND \leftarrow SSTHRESH + 3 \text{ MSS}$.
  • Timeout: $SSTHRESH \leftarrow \lfloor CWND / 2 \rfloor$, $CWND \leftarrow 1 \text{ MSS}$ (Collapse to Slow Start).

6. Network Layer: Dijkstra vs. Distance Vector Routing

Dijkstra's Link-State Algorithm: Computes least-cost paths globally with complexity $\mathcal{O}(|V|^2)$ by iteratively relaxing distances from the visited vertex set $S$.
Distance Vector Routing (Bellman-Ford): Distributed routing where nodes periodically exchange distance vectors with neighbors:

D_x(y) = min_v { c(x, v) + D_v(y) } for all neighbors v of x

When a link is severed (e.g., ED-ICU cable failure), the routing engine immediately re-computes alternative shortest paths around the failure (e.g., AMB → ED → OT → SRV → ICU).

8. Conclusion & Future Scope

  • Achieved prioritized zero-drop transmission for emergency Code Blue alerts.
  • Validated dynamic real-time rerouting under link failure conditions using Dijkstra and Distance Vector algorithms.
  • Provided full simulation integration with genuine Wireshark .pcap generation, NS-2 .tcl, and NS-3 .cc scripts.
